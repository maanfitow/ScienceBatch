# Automation Interfaces QA

**Status:** Linux implementation verified for the automation scenarios below, not cross-platform release certification. Headless CLI, MCP, Skills, and focused native workspace evidence are recorded separately. Existing writing-ribbon QA classifications are unchanged.

## Headless CLI evidence

The debug `sciencebatch-cli` binary ran multi-file LaTeX and Typst projects containing nested source files, project metadata, a PNG asset, and a local bibliography. For both engines, inspect, preflight diagnostics, and explicit compile/export returned exit 0. The captured PDFs were 18,185 bytes for LaTeX and 24,258 bytes for Typst. Preflight output correctly states that it does not check syntax completeness, dependency availability, or editor-linter rules.

Project operation receipts recorded successful create, inspect, and compile flows for both engines, along with read, literal search, and guarded apply cases. Negative cases recorded expected exits for malformed usage, missing LaTeX inputs, empty main-source preflight, stale hash, and symlink inventory. LaTeX worker path escape was rejected with `path.outside_project`. Typst included-source syntax and missing-dependency cases returned compiler diagnostics.

The first captured negative receipts exposed two issues and are preserved as history. The later retest in `retest-results.json` confirms both are fixed: a Typst `../outside.typ` include now returns exit 2 with `path.outside_project`, and a missing LaTeX index in offline mode returns exit 3 with `cache.unavailable_offline`. The retest also confirms precise compiler locations for an included LaTeX error (`sections/body.tex`, line 2) and a main-file error (`main.tex`, line 3), both returned as `compile.document_failed` with exit 1. Typst resource preparation completed from the bundled cache with zero downloaded bytes and zero files prepared.

## Isolation and subprocess evidence

Linux `strace` receipts for LaTeX and Typst offline compiles reported no `AF_INET`/`AF_INET6` connections and no intermediate-file writes. The headless worker returned PDFs while keeping the original project source out of the worker's filesystem reads. The worker test receipts recorded timeout as exit 124, handled interruption as exit 130, and crash as exit 4; all three reported the child worker reaped.

The cached-bundle offline runs completed without network connections. The no-digest case produced `cache.unavailable_offline` and exit 3. Unit tests cover the resource download budget, including exact-boundary EOF, overflow rejection, and exclusion of cached reads. A supervised preparation-worker test covers timeout and child reaping with a short deadline. Full preparation of the approximately 2.7 GiB resource bundle was not run; real large-download duration and resume after interruption remain unverified.

The public resource limits were exercised separately. The CLI rejected source text over 8 MiB, assets over 32 MiB, traversal depth 65, and 10,001 entries with exit 3 and `resource.limit_exceeded`; a FIFO/special file was rejected with exit 2 and `path.symlink_rejected`. These are Linux results only.

The full CLI matrix and syscall-isolation script passed again on October 8, 2026, with the GUI closed and `DISPLAY`/`WAYLAND_DISPLAY` unset: `node scripts/test-automation-cli.mjs --cli src-tauri/target/debug/sciencebatch-cli`. It covers the disk operations, both engines, malformed and boundary inputs, guarded apply, export, timeout/interruption/crash cleanup, and Linux `strace` checks. Final fixtures and traces were `/tmp/sciencebatch-automation-cli-moq3lz/`.

Review found that the earlier script's strace PID parser accepted only bracketed PIDs, whereas file traces used plain PIDs. That script assertion could therefore skip the worker-read check. It now accepts both forms and requires a worker exec and parseable PID. The final six traces cover LaTeX, Typst, stale cache-check time, stale digest time, missing index, and missing digest. Every trace asserts no IPv4/IPv6 network syscall, no worker open within the original project, and no compiler intermediate writes anywhere. Missing-cache cases return exit 3 with `cache.unavailable_offline`. All cache mutations use temporary copies; the user's cache is preserved.

The integrated Rust suite passed 97 library tests and all three MCP integration tests on October 8, 2026 (`cargo test --manifest-path src-tauri/Cargo.toml`). A separate vendored `tectonic_bundles` preparation-budget test also passed. An intermittent `ETXTBSY` in the fake-worker fixture was fixed by publishing closed scripts into private unique directories; the focused supervisor test then passed five repeated runs and the complete library suite. Production timeout/cancellation assertions were not weakened.

## MCP and workspace evidence

Three MCP SDK integration tests passed. They exercised authorized LaTeX and Typst compile calls, revision and permission handling, and workspace compile cancellation notifications using a fake authenticated bridge. The cancellation case used an infinite TeX job, verified notification and child reaping, then confirmed the server remained usable. A workspace compile failure was returned as an MCP tool error with its diagnostic. Bridge security receipts confirmed owner-only registry permissions, invalid-token rejection, root-scope denial, and explicit selection of a second app instance.

On the Linux debug GUI, the workspace agent exercised a live Monaco edit followed by Undo and Redo. Bridge reads observed buffer revisions 1, 2, and 3; these edits did not compile or update the PDF preview. The native bridge also exercised revision conflict, dirty-close protection, and explicit save. These are focused workspace observations, not full native compile/export acceptance.

On October 8, 2026, `scripts/test-workspace-native-qa.mjs` passed ten scenarios against the current Tauri debug app and Vite frontend. The [token-free native receipt](qa/automation-native-linux-2026-10-08.json) records the environment, scenarios, and limitations. The run verified unsaved LaTeX main/secondary/`.sty` overlays in exported PDF text; native Edit-menu Undo/Redo with increasing revisions; stale revision and dirty-close conflicts; a compile-owned Git repository guard rejecting a live edit; save-only behavior; compiler failure diagnostics; refusal of implicit overwrite; successful explicit overwrite; rejection of a result made stale by an edit during compilation; cancellation with worker reaping; full readback of a 2 MiB one-line edit in 411 ms; rejection above 8 MiB; and Typst main/secondary overlays in exported PDF text.

Native execution exposed React render races when opening files, activating the editor for an edit, and closing a project. The bridge now waits for the expected rendered state while preserving the caller's original context and revisions. A timer fallback bounds waits when animation frames are paused. No compile was added to any open/edit/save/close operation.

This is focused automation acceptance. The `.sty` overlay is verified in compiler output, but Monaco's macro markers were not asserted directly. PDF canvas zoom/scroll and previous writing-ribbon native cases are not certified by these scenarios. No Windows or macOS run is recorded.

A final macro-context lifecycle check verified live `.cls`/`.sty` definitions, no rescan for ordinary main-source changes, and restoration of disk macros when a style/class buffer is discarded and closed. `setTabs` now recomputes context when those open sources change. This is a focused runtime check of the macro registry, not a native Monaco-marker assertion.
