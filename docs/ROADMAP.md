# Product Roadmap

This document recommends an order for future product work based on the current repository and ScienceBatch's offline desktop focus. It records a proposal for discussion; it does not approve new implementation scope.

[IDEAS.md](../IDEAS.md) owns product proposals and open questions. [SPECS.md](../SPECS.md) owns technical requirements and acceptance criteria. Document order does not imply approval or delivery commitment.

## Current product foundation

ScienceBatch supports local multi-file LaTeX and Typst projects, a nested project explorer, file and folder management, asset import, project search, ZIP import and export, central source/asset/diff/PDF tabs, and local Git workflows. The first local Git application stage is integrated into `develop`; provider accounts/OAuth, API repository creation, pull requests, merge requests, hosted authenticated-push validation, and cross-platform QA remain pending for a later Git phase. See [IDEA-009](../IDEAS.md#idea-009-local-git-actions), [SPEC-GIT-004](../SPECS.md#spec-git-004-commits-cloning-remotes-and-transfer), and [Git workflow guidance](GIT_WORKFLOWS.md).

The LaTeX and Typst writing ribbon and Bold/Italic formatting are also integrated into `develop`. Merge provenance is recorded in the [final review](WRITING_RIBBON_FINAL_REVIEW.md). Native/release checks remain open; integration does not convert summary-only or unverified native cases into verified passes.

## Active delivery and next priorities

1. **Complete release validation of the automation delivery.** [IDEA-008](../IDEAS.md#idea-008-cli-mcp-and-skills) is implemented on `feat/automation-interfaces` under [SPEC-CLI-001](CLI_SPEC.md), with baseline local commit `e0c9693`. Real full-bundle preparation, interruption/resumption, and a zero-download warm pass are verified on Linux in the separate [resource report](AUTOMATION_RESOURCES_QA.md). Publication and merging remain separate. The delivery covers the headless CLI, local stdio MCP server, guarded project operations, both compilation engines, explicit resources, live workspace bridge, and eight versioned Skills. Use [Automation Interfaces](AUTOMATION.md) for permissions, installation, and examples, and [Automation QA](AUTOMATION_QA.md) for Linux evidence and remaining release limits, including cross-platform checks. Keep verification claims limited to checks actually completed.
2. **Complete native validation of the writing ribbon and formatting.** LaTeX symbols/tables/matrices, Typst symbols/tables/matrices, and Bold/Italic are integrated into `develop`; browser/compiler evidence is recorded in the linked QA documents. Native acceptance remains incomplete. Preserve every existing status: Antigravity's summary-only reports are not independently evidenced passes, and the embedded-PDF fixture, actual Git-lock interaction, native formatting, Cancel/Undo/Redo, and clipboard-failure behavior remain unverified. See [Writing Ribbon QA](WRITING_RIBBON_QA.md), [native evidence](WRITING_RIBBON_NATIVE_QA.md), [T1](TYPST_SYMBOLS_QA.md), [T2](TYPST_STRUCTURES_QA.md), and [formatting](TEXT_FORMATTING.md). The `occurrencesHighlight: 'off'` mitigation and its accepted loss of semantic occurrence highlighting remain recorded in [final review](WRITING_RIBBON_FINAL_REVIEW.md).
3. **Validate PDF preview behavior in native Tauri.** Use a real document with embedded PDF figures and inspect affected pages after Fit to width/screen and several zoom changes. Also verify the Git-lock UI when the native QA environment is available. The missing-content report is intermittent and not a confirmed current failure; fix only if it reproduces. See [Bug 1](../BUGS.md#bug-1-pdf-preview-intermittently-loses-content-while-zooming), the [PDF preview investigation](PDF_PREVIEW.md), and the [writing ribbon QA record](WRITING_RIBBON_QA.md).
4. **Keep Visual/Review modes and real-time collaboration as separate future proposals.** Resolve document synchronization, review-state, hosting, offline editing, and conflict behavior before prioritizing [SPEC-WRITE-003](../SPECS.md#spec-write-003-views-and-editing-modes) or [IDEA-010](../IDEAS.md#idea-010-real-time-collaboration). The `sciencebatch-review` Skill is a read-only automation workflow, not a Visual/Review product mode.

These priorities are recommendations for discussion. Reorder them when user needs or validation results warrant it.
